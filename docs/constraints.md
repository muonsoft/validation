# Constraint catalog

Choose a constraint from `it` for translated violations, property paths, conditions,
and groups. Use `validate` for a standalone error or `is` for a boolean result.
The table lists constructors and related helpers; follow API links for options
and exact signatures. A dash means that package has no corresponding helper.

## Choosing arguments

Use `validation.String`, `Number`, `Bool`, or `Time` with typed constraints, and
`NilString`, `NilNumber`, `NilBool`, or `NilTime` for pointers. Required/blank/nil
constructors have `Number` and `Comparable` variants for generic values.
Use `Countable(len(values), ...)` for collection size, `Comparables` for uniqueness,
and `Slice` with `HasUniqueValuesBy` for uniqueness by a key.

`validation.This` and `Each` accept constraints implementing `Constraint[T]` for
the input type. File content constraints accept `[]byte` through these arguments.
See [Usage](usage.md), [Property paths and structs](property-paths-and-structs.md),
and [Custom constraints](custom-constraints.md).

Most string format checks skip empty values; required-value rules and some other
constraints differ. See [Empty and required values](usage.md#empty-and-required-values).
Standalone helpers can have different option signatures from their `it` counterparts.

## Controlling execution

Use `validation.When` or a constraint's `When` for conditions, `WithGroups` with
`WhenGroups` for group selection, `Sequentially` to stop after the first failing
argument, and `AtLeastOneOf` for alternatives. `All` collects violations from all
arguments; `Async` executes arguments concurrently. Non-violation errors stop
validation. Shared custom constraints used concurrently must support concurrent calls.

See the [flow-control examples](../example_test.go) and
[group guide](property-paths-and-structs.md#conditional-validation-based-on-groups).
